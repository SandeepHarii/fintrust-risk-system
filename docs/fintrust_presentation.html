01 · BUSINESS PROBLEM

Manual transaction review doesn't scale

FinTrust's operations team receives transaction exports that must be processed consistently and reviewed for risk. The current flow is manual, slow, and hard to audit.

Today

Manual, error-prone

Flat files land on a shared drive. An analyst opens each CSV, scans it by eye, and copies suspicious rows into a spreadsheet for follow-up.

Business impact

Slow, expensive, unauditable

No structured audit trail. Risk decisions aren't reproducible. High-risk patterns surface in hours instead of seconds, and there's no way to prove which rule fired on which transaction.

The brief

Automate the flow end-to-end

From ingestion to risk scoring to alerting — with a REST API, scheduled reporting, structured logs, and POPIA-aligned governance within the AWS Free Tier.

02 · SOLUTION

An event-driven serverless platform

CSV uploads flow through validation, risk scoring, and multi-store persistence, then surface to compliance via REST API, automated alerts, and a scheduled S3 report. Every stage runs on AWS within the Free Tier.

Ingest

CSV to S3

Operations team uploads transaction CSVs. S3 triggers the ingest Lambda; invalid rows are quarantined automatically.

Score

Rule-based risk engine

SQS queues transactions per account. The score Lambda applies HIGH_AMOUNT, HIGH_VELOCITY, and CROSS_BORDER rules.

Store

RDS + DynamoDB

RDS PostgreSQL holds the auditable ledger; DynamoDB stores risk scores for fast lookup by account and timestamp.

Serve

API + alerts + reports

API Gateway exposes data to compliance. SES emails on HIGH risk. EventBridge schedules a monthly report to S3.

04 · KEY FUNCTIONALITIES

What the user can do

Upload & ingest

Live CSV upload

Upload a CSV through the dashboard's drop zone. The ingest Lambda validates each row, quarantines invalid records, and persists valid rows to RDS and DynamoDB.

Explainable classifications

Every transaction is scored against three named rules and classified LOW, MEDIUM, or HIGH. The rule that fired is visible on every row — no black box.

06 · DATA FLOW

Upload to alert, in six stages

01 · Upload

S3 raw bucket

KMS-encrypted. Lifecycle rule to Glacier after 7 years.

02 · Ingest

ingest.py

S3 trigger. Validates each row. Quarantines failures.

03 · Queue

SQS FIFO

Ordered per account. DLQ wired for resilience.

04 · Score

score.py

Applies three named rules. Produces LOW / MEDIUM / HIGH.

05 · Store

RDS + DynamoDB

Ledger in PostgreSQL. Risk scores in DynamoDB.

06 · Alert

alert.py

SES email to compliance on HIGH risk transactions.

Separately, query.py serves the compliance API behind API Gateway, and report.py writes a monthly CSV and JSON report to S3 on an EventBridge schedule.

C5

Named AWS controls

Risk register

  • PII exposure — KMS CMK + S3 bucket policy
  • Credential leak — Secrets Manager rotation
  • Data loss — S3 versioning + RDS snapshots
  • Over-permissioned roles — IAM least privilege per Lambda
  • Unencrypted storage — KMS on all S3 buckets
